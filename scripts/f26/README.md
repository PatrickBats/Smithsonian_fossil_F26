# Fall 2026 priority data scripts

These are the scripts used for the October 1 [data status update](../../docs/F26_DATA_PROGRESS_2026-10-01.md), with October 7 guards added after Dr. Barman clarified that `/projects` is not for data storage and `/rhf/allocations` is for data storage. They are provided for review and later reproduction with authorized sponsor data. This repository intentionally excludes the sponsor ZIP, NDPI/NDPA files, row-level annotation and split manifests, PNG/HDF5 crops, and credentials. **Do not run a shared export while the RHF group quota is full.**

The scripts preserve the original source files. The split is a review draft; the only complete image export so far is the local 2D baseline. The multifocal code is a **three-object pilot**, not a full extraction pipeline.

## Sequence and private inputs

1. `inventory/build_f26_annotation_manifest.py` reads `Fall_2026.zip`, the verified NOTS file-location CSV, and the two sponsor title/category tables. It writes an 11,502-row annotation inventory, category support, and alias-overlap reports to `--output-dir`. Supply `--archive`, `--file-manifest`, `--title-counts`, and `--category-totals` explicitly. Requires `openpyxl`.
2. `inventory/build_f26_priority_candidates.py --source /secure/path/f26_annotation_manifest.csv --output-dir /secure/path` selects the 2,283 current priority candidates and records seven exclusions. It checks the exact observed F26 counts; a changed source version will stop for review.
3. Put those two outputs in a private `inputs/` folder as `f26_priority_candidates.csv` and `f26_priority_exclusions.csv`. Set `F26_SPLIT_ROOT` to that folder's parent before running `split_priority_v0/build_split.py` and `verify_bundle.py`. The builder uses NumPy and SciPy 1.15.3; the verifier uses only the standard library. The builder refuses `/projects` as an output. A local private working directory is acceptable for review; a shared row-level split belongs in a separate RHF data directory after capacity is available.
4. The 2D exporter expects a private copy of `record_assignments.csv` at `$F26_CROP_ROOT/inputs/`. `crops_priority_v0/preflight.py` checks all geometry before export. `export_crops.py --mode pilot` writes nine examples, and `--mode full` stages images before finalizing `images/`. `verify_export.py` checks hashes and provenance. The write commands require `F26_CROP_ROOT` to name a **new child** of `/rhf/allocations/dsci435/Smithsonian_F26/processed/`; without it, they refuse the old `/projects` path. The earlier Slurm launch scripts that pointed at `/projects` were removed from this PR. Review RHF quota, job resources, environment, and existing outputs before making a new launcher. Requires OpenSlide and Pillow. Never overwrite a completed output. The original 2D set is already verified locally; copying it after capacity is restored is preferable to repeating extraction without need.
5. `crops_priority_v0/remote_stream_batch.py` is the read-only NOTS tar-stream fallback used to build the complete 2D baseline locally after quota failure. It relies on the deployed private split input and `export_crops.py` and receives `F26_BATCH_START` and `F26_BATCH_END` as source-image index bounds. `stream_to_local.py` is the local receiver: set `F26_SSH_HOST` to your own NOTS login, optionally `F26_SSH_CONTROL_PATH`, and review `F26_REMOTE_ROOT` and `F26_REMOTE_PYTHON` before use. It saves resumable batches under `local_export_staging/` and finalizes `local_images/`; `verify_local_export.py` checks the finished directory. Both output directories stay outside Git.
6. `multifocal_priority_v0/preflight_h5_coverage.py` checks historical HDF5 tile geometry against the proposed F26 crop regions. `probe_ndpi.py` reads sample focal planes. `remote_pilot_stacks.py` streams three object HDF5 focal stacks to stdout as a tar archive without remote writes. These scripts expect the private split input and 2D geometry preflight under the existing NOTS crop root. Requires `h5py`, `numpy`, `tifffile`, `zarr`, and, for the probe, OpenSlide. The pilot output is **not** the full dataset.

## Storage and review safeguards

- Source NDPI/NDPA paths in private manifests must remain read only. Never replace files in the historical allocation.
- `/projects/dsci435/Smithsonian_F26/` is **not an approved data-storage tree**. The historical split bundle and partial 2D staging there are misplaced data pending verified cleanup. Read-only probes may still use the historical input paths, but no new dataset output belongs there.
- The RHF allocation `/rhf/allocations/dsci435/` is the designated data-storage filesystem. Its group quota was last reported at the hard limit. The proposed `Smithsonian_F26/` subdirectories are project organization, not exact paths specified by Dr. Barman; do not create outputs until capacity and the layout are checked.
- The code uses expected F26 counts and output-path guards for this exact run. A new dataset version, output location, environment, or split requires review and explicit updates; do not remove guards just to make a run pass.
- The existing pilot does not decide whether the desired final output is object-centered stacks or full-frame slide stacks. That scope and the destination remain open.
