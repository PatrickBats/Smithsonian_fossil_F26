# Frozen DINOv2 classifier trial

Patrick authorized trying DINO after the Swin comparisons. This first trial uses the official DINOv2 ViT-B/14 backbone pretrained on LVD-142M, frozen in evaluation mode, with a newly fitted 32-category linear classifier. Source: [Meta's code and pretrained models](https://github.com/facebookresearch/dinov2). The exact source commit, downloaded weight SHA-256 and runtime versions are recorded with the run.

Inputs are the verified Tenengrad crops at the same full-crop 224-pixel resolution and ImageNet normalization as Swin. Extract the final normalized CLS token concatenated with the average normalized patch token (1,536 features). There is no image augmentation or backbone fine-tuning in this initial probe. It compares complete methods, not architecture alone: pretraining, architecture, representation and training strategy all differ from the Swin run.

Only the 1,952 non-test specimens enter the backbone. Reuse these deterministic, frozen features for two independently trained classifiers: the existing slide-separated split and the existing specimen-level shared-slide split. Both contain 1,605 training and 347 validation specimens. The same 331 test specimens remain reserved; no test features or model predictions are computed.

For each split, fit StandardScaler on its training features only, then multinomial L2 logistic regression with C=1, LBFGS, tolerance 1e-6 and maximum 5,000 solver iterations. This is one fixed configuration, not a validation hyperparameter search. Failure to converge stops the run and records the error; iteration count and finite-value checks are recorded. No category weighting, oversampling, additional source data, or category changes are included.

Compare validation accuracy, macro-F1 over represented categories, balanced accuracy, confusion matrices and per-class results against Swin on the identical respective split. The grouped validation has 31 represented classes; shared-slide validation has 32. Comparisons across the two split types do not isolate slide effects because membership and category support differ.

Code: [train_dino_probe.py](../../scripts/classification/train_dino_probe.py). Execution is detached on Terminator6 with a UUID GPU lock for feature extraction; the small classifiers fit on CPU. Outputs remain outside Git under `/mnt/richb/pb52/MADness/smithsonian/dino_probe_2026-10-07/attempt_02/`. `status.json`, `summary.json`, `provenance.json`, and each split's `validation_metrics.json` record progress and results. The frozen probe completed in 82 seconds including verification/model loading; both linear solvers converged (534 and 553 iterations). Separate-slide validation: accuracy 29.97%, macro-F1 0.2475, balanced accuracy 29.94%. Shared-slide validation: accuracy 59.08%, macro-F1 0.5278, balanced accuracy 52.49%. This initial frozen-feature method underperformed fine-tuned Swin on both identical splits; it does not establish how fine-tuned DINO would perform. No Git push or test inference is included.

The first attempt stopped during Git provenance verification before model loading. The exact official checkout was added to Git safe.directory and the same experiment restarted in attempt_02; failed-run evidence is preserved. No scientific settings changed.
