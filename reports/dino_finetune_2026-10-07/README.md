# DINOv2 last-two-block fine-tuning

Patrick authorized backbone fine-tuning after the frozen DINOv2 trial. Two independent runs use the existing separate-slide and shared-slide assignments, each with 1,605 training and 347 validation specimens. The original 331 test specimens remain reserved. The same 32 categories, Tenengrad crop geometry, full-crop 224-pixel resize, and normalization are retained.

Each run starts independently from the official DINOv2 ViT-B/14 LVD142M checkpoint and a fresh 32-output linear head on concatenated normalized CLS and mean patch features. Three epochs train only the head (AdamW, learning rate 0.001); 37 further epochs train the head (0.0001), transformer blocks 10–11, and the final backbone normalization (0.00001). The first ten blocks and patch embedding remain frozen. Weight decay is 0.01, batch size 32, seed 20261007, float32, deterministic algorithms, gradient clipping at 1, ordinary sampling and unweighted cross-entropy. Training-only quarter-turns and horizontal flips match the Swin augmentation policy.

This changes both adaptation and the classifier training procedure relative to the frozen probe (which used training-only StandardScaler and logistic regression without augmentation). It is a comparison of methods, not an isolated ablation of unfreezing. No class balancing, test selection, additional data, or hyperparameter sweep is included. Checkpoints are selected by macro-F1 over categories present in the corresponding validation set (31 for separate slides, 32 for shared slides).

Each GPU runs a two-epoch smoke test before a fresh 40-epoch run. The code verifies source metadata, crops, fixed assignments and numerical finiteness, records trainable parameter names, and hashes all permanently frozen parameters before and after training to ensure they do not change. Checkpoints, optimizer/RNG state, validation predictions, histories, script snapshots and software versions are retained.

Training runs detached on two UUID-locked Terminator6 GPUs. Local staging is outside Git at `/mnt/richb/pb52/MADness/smithsonian/dino_finetune_2026-10-07/`. Following Patrick's instruction to use RHF, successful run folders are copied to `/rhf/allocations/dsci435/Smithsonian_F26/runs/dino_finetune_2026-10-07/` and each copied file is SHA-256 verified. A 1 MiB RHF write probe succeeded; this does not guarantee that a large future transfer will fit. Transfer failures are recorded and local originals retained. No automatic deletion or Git push occurs.

At launch the experiment is in progress. The supervisor's `status.json` distinguishes training, copying and completion; each split has separate smoke/full status and failure logs. `summary.json` and `rhf_verification.json` are written upon successful completion.
